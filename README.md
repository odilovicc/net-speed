# net-speed

[![CI](https://github.com/odilovicc/net-speed/actions/workflows/ci.yml/badge.svg)](https://github.com/odilovicc/net-speed/actions/workflows/ci.yml)
![Node.js ≥ 20.3](https://img.shields.io/badge/node-%E2%89%A5%2020.3-brightgreen)
![zero dependencies](https://img.shields.io/badge/dependencies-0-blue)

Консольная утилита для замера скорости скачивания. Она делает к указанному адресу
10 последовательных HTTP(S)-запросов, на каждом дожидается полного ответа, а потом
печатает среднее время запроса, общий объём скачанного и итоговую скорость.

```
$ net-speed https://proof.ovh.net/files/10Mb.dat
Замер скорости https://proof.ovh.net/files/10Mb.dat
Запросов: 10, последовательно; таймаут: 30 с

#   Статус  Размер      Время     TTFB      Скорость
1   200     10.49 МБ    1.59 с    418 мс    52.78 Мбит/с
2   200     10.49 МБ    1.41 с    389 мс    59.47 Мбит/с
3   200     10.49 МБ    452 мс    96 мс     185.66 Мбит/с
...
10  200     10.49 МБ    828 мс    98 мс     101.34 Мбит/с

Итого
  Успешных запросов:      10 из 10
  Скачано всего:          104.86 МБ (104 857 600 байт)
  Среднее время запроса:  785 мс  (медиана 664 мс, мин 442 мс, макс 1.59 с, σ 413 мс)
  Среднее TTFB:           159 мс
  Скорость скачивания:    106.84 Мбит/с  (13.35 МБ/с)
```

## Требования

Нужен только **Node.js 20.3 или новее**. Внешних зависимостей нет: используются
встроенные `fetch`, `node:util.parseArgs` и `node:test`, поэтому `npm install` не нужен.

```bash
node --version   # v20.3.0 или выше
```

## Запуск

```bash
git clone https://github.com/odilovicc/net-speed.git
cd net-speed

node bin/net-speed.js <url>
# или
npm start -- <url>
```

Чтобы команда `net-speed` была доступна глобально:

```bash
npm link
net-speed https://proof.ovh.net/files/10Mb.dat
```

### Опции

| Опция                 | По умолчанию | Описание                                                       |
| --------------------- | ------------ | -------------------------------------------------------------- |
| `<url>`               | —            | Адрес для скачивания. Если схема не указана, подставляется `https://` |
| `-n, --count <число>` | `10`         | Сколько запросов сделать (от 1 до 1000)                        |
| `-t, --timeout <сек>` | `30`         | Таймаут на один запрос, включая скачивание тела                |
| `--cache-bust`        | выкл.        | Добавлять к URL уникальный `?_nocache=…`, чтобы CDN не отдавал файл из кэша |
| `--json`              | выкл.        | Вывести результат в JSON, удобно для скриптов и CI             |
| `-h, --help`          |              | Справка                                                        |
| `-v, --version`       |              | Версия                                                         |

### Примеры

```bash
# 10 запросов к тяжёлой картинке (адрес можно указать без https://)
node bin/net-speed.js example.com/path/to/big-image.jpg

# Тестовые файлы OVH (10 МБ, 100 МБ, 1 ГБ), не ограничивают частоту запросов
node bin/net-speed.js https://proof.ovh.net/files/10Mb.dat

# 5 запросов к 100-мегабайтному файлу с таймаутом в минуту
node bin/net-speed.js https://proof.ovh.net/files/100Mb.dat -n 5 -t 60

# Достать только скорость в Мбит/с
node bin/net-speed.js https://proof.ovh.net/files/10Mb.dat --json | jq .summary.mbps
```

## Единицы измерения

| Величина      | Единица                                    |
| ------------- | ------------------------------------------ |
| **Скорость**  | **Мбит/с**, мегабиты в секунду (1 Мбит = 10⁶ бит). В скобках та же скорость в МБ/с |
| Объём         | МБ, мегабайты (1 МБ = 10⁶ байт), плюс точное число байт |
| Время         | мс или с                                   |

Основная единица — Мбит/с, потому что в ней указывают тарифы провайдеров и
результаты speedtest.net, так что цифры можно сравнивать напрямую. Все приставки
десятичные (СИ): 1 МБ/с = 8 Мбит/с.

В режиме `--json` объём отдаётся в байтах, время в миллисекундах, скорость в полях
`summary.mbps` (Мбит/с), `summary.megabytesPerSecond` (МБ/с) и `summary.bytesPerSecond`.

## Как считается

- **Время запроса** — от отправки запроса до получения последнего байта тела.
  Отдельно показывается **TTFB**, время до прихода заголовков ответа.
- **Среднее время** — среднее арифметическое времени успешных запросов. Рядом выводятся
  медиана, минимум, максимум и стандартное отклонение, по которым видно, насколько
  стабилен канал.
- **Общий объём** — сумма байт тела всех успешных ответов, посчитанная по потоку,
  а не по заголовку `Content-Length`.
- **Скорость** = общий объём / суммарное время запросов. Это то же самое, что
  «средний объём / среднее время». Среднее арифметическое скоростей отдельных
  запросов не используется, потому что его завышают короткие быстрые запросы.

### На что обратил внимание

- **Запросы строго последовательные.** Следующий начинается только после того,
  как тело предыдущего дочитано.
- **Тело не держится в памяти.** Байты считаются по мере прихода чанков, так что
  можно мерить хоть гигабайтные файлы.
- **Сжатие отключено** через `Accept-Encoding: identity`. Иначе `fetch` распаковал бы
  gzip/brotli, и мы посчитали бы распакованный объём вместо реально скачанного.
- **Кэш.** Отправляются `Cache-Control: no-cache` и `Pragma: no-cache`. Если CDN их
  игнорирует, поможет `--cache-bust`.
- **Keep-alive.** Соединение переиспользуется между запросами, как в обычном
  браузере, поэтому первый запрос дольше (DNS, TCP, TLS). Это видно по TTFB в таблице.
- **Первый запрос проверяет адрес.** Если ссылка неверная (DNS не резолвится, 404,
  сервер недоступен, таймаут), остальные 9 запросов не отправляются, а утилита сразу
  сообщает об ошибке:
  ```
  1   404     ошибка: HTTP 404 Not Found

  Первый запрос не удался — замер остановлен, не отправлено запросов: 9. Проверьте адрес.
  ```
  В JSON в этом случае `"stoppedEarly": true`.
- **Ошибки после успешного первого запроса не роняют замер.** Не-2xx ответ, таймаут или сетевая ошибка попадают
  в таблицу, а статистика считается по успешным запросам. Пригодится, например,
  на публичных хостингах картинок вроде Wikimedia: после нескольких запросов подряд
  они начинают отвечать `429 Too Many Requests`.
- **Ctrl+C** останавливает замер и выводит итог по уже выполненным запросам.
  Повторный Ctrl+C завершает процесс сразу.
- Редиректы обрабатываются автоматически.

### Коды выхода

| Код   | Значение                                     |
| ----- | -------------------------------------------- |
| `0`   | Хотя бы один запрос успешен, скорость посчитана |
| `1`   | Первый запрос не удался (неверная ссылка) или все запросы завершились ошибкой |
| `2`   | Неверные аргументы командной строки          |
| `130` | Прервано через Ctrl+C                        |

## Тесты

```bash
npm test                # все тесты, Node.js 20+
npm run test:coverage   # с отчётом о покрытии, Node.js 22+
```

Тесты написаны на встроенном `node:test` и поднимают локальный HTTP-сервер,
поэтому интернет для них не нужен. Всего 122 теста, прогон занимает меньше секунды.
Покрытие `src/`: 100% строк и функций, около 97% веток.

| Файл | Что проверяет |
| --- | --- |
| `measure.test.js` | подсчёт байт по потоку, редиректы, HTTP-ошибки, таймаут, сетевые ошибки, cache-bust, отмена |
| `measure.edge.test.js` | chunked без `Content-Length`, `204`, таймаут до заголовков и посреди тела (частичные байты сохраняются), бесконечный редирект, **строгая последовательность** (сервер фиксирует, что одновременно активен максимум один запрос), продолжение после ошибок |
| `stats.test.js`, `stats.edge.test.js` | формулы на известных значениях; инварианты на 200 случайных наборах (скорость = средний объём / среднее время, min ≤ median ≤ max); независимость от порядка запросов, деление на ноль, иммутабельность; границы единиц (999.95 КБ → «1.00 МБ», 999.5 мс → «1.00 с») |
| `cli.test.js`, `cli.output.test.js` | разбор и валидация аргументов, таблица, частичные ошибки, совет про маленький файл, прерывание, цвета (TTY, `NO_COLOR`, `TERM=dumb`), структура и согласованность JSON, коды выхода |
| `fail-fast.test.js` | после неудачного первого запроса (404, 500, DNS/отказ соединения, таймаут, бесконечный редирект) сервер получает ровно один запрос; ошибки после успешного первого запроса замер не останавливают; сообщение и `stoppedEarly` в JSON; e2e с недоступным адресом |
| `e2e.test.js` | запуск настоящего бинарника отдельным процессом: коды выхода 0/1/2, JSON, **Ctrl+C → код 130** с итогом |

CI в GitHub Actions гоняет тесты на Linux, macOS и Windows с Node.js 20, 22 и 24, а на Node 24
дополнительно проверяет, что покрытие не опустилось ниже порога.

## Структура

```
bin/net-speed.js     исполняемый файл: Ctrl+C, код выхода
src/cli.js           разбор аргументов и вывод (функция run() без side-effects)
src/measure.js       HTTP-запросы и замер времени и объёма
src/stats.js         агрегирование: среднее, медиана, σ, скорость
src/format.js        единицы измерения и форматирование
test/helpers.js      локальный тестовый сервер и заглушки потоков
test/*.test.js       тесты
```
